# Security Policy

## Supported versions

Security fixes are applied to the current `main` branch. This project does not
maintain older release branches unless a release announcement explicitly says
otherwise.

## Reporting a vulnerability

File a **Security concern** issue using the repository's GitHub issue template.
The template records only the information maintainers need to triage the report
and tells contributors how to request a private follow-up channel.

Do not include any of the following in the issue:

- Customer SSP source documents or CUI.
- Credentials, tokens, account identifiers, or production URLs.
- Exploit payloads or operational details that could increase impact.

Include the affected public-core version or commit, a high-level impact
description, and safe reproduction or mitigation information. Maintainers will
acknowledge the issue and establish an approved private transfer method before
requesting sensitive artifacts.

We will acknowledge receipt, assess scope and severity, coordinate remediation,
and disclose publicly only after a fix or mitigation is available.
